One proxy between drift and downtime.

AutoPatch compares every JSON response to a baseline contract. When the shape changes, it maps the new payload back, verifies the mapping in code, and serves the response your client already understands.

  3. 03

export function adaptCheckoutUser(raw: UpstreamPayload): ClientUserContract {
  return {
    user_id: String(raw.id ?? ''),
    email: String(raw.contact?.email_addr ?? ''),
    account_balance: Number(raw.balance ?? 0),
    is_verified: Boolean(raw.verified),
    created_at: typeof raw.created === 'number'
      ? new Date(raw.created * 1000).toISOString()
      : String(raw.created ?? new Date().toISOString())
  };
}

Questions the demo should answer.

How does AutoPatch map fields without hallucinating?

The model proposes field paths only, such as contact.email_addr to email. Deterministic code applies those paths to the observed payload and runs the five gates. If any gate fails, the rule is rejected.

What happens if an upstream deletes a required field?

AutoPatch refuses to fabricate data. It returns HTTP 502 with the missing field in the diagnostic, so the client fails loudly instead of rendering a made-up value.

Which models can run the cold heal?

Groq, Gemini, or the offline mock mapper. The mock mapper is labelled in the console, so a demo never pretends a live model was used.

Does a cached heal call the model again?

No. A verified rule is cached by structural fingerprint. Later requests with the same shape apply the rule locally. The console shows the measured p50 for cold and cached heals.

What does the autonomous pull request contain?

A feature branch, a typed TypeScript adapter, a node:test suite, and a pull request body with the fingerprint and mapping diff. The adapter is verified in-process before the branch is written.
