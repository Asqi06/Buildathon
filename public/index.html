06 // FREQUENTLY ASKED QUESTIONS

Technical Specifications

Everything you need to know about fail-closed execution, latency guarantees, and compliance.

How does AutoPatch guarantee zero hallucinations on financial fields? +

The AI model only proposes source field JSON paths (e.g. contact.email_addr → email). It never writes response data. Deterministic in-process code applies the path extraction and validates it through Gate 5. If a required field cannot be found, AutoPatch immediately returns HTTP 502 with diagnostics. It never invents values.

What is the latency overhead on live requests? +

Cached rules execute locally in-memory in 0.14 ms. On an initial cold drift miss, Gemini 2.0/3.8 Flash synthesizes the mapping in ~420 ms. Once verified by the 5-Gate safety engine, the rule is cached by SHA-256 structural fingerprint, making all subsequent requests instantaneous.

Does AutoPatch transmit customer PII to external LLMs? +

No. AutoPatch enforces a strict Zero-PII Sanitization Layer. Before any schema structure is sent to Gemini, all user data values are scrubbed into abstract type skeletons (e.g. "alex@domain.com" → "<STRING_EMAIL>", 4999 → "<NUMBER>"). The AI only sees keys and types, never customer data.

How does autonomous pull request generation work? +

When a cold heal is verified in runtime, an asynchronous worker generates a clean TypeScript adapter module along with a node:test regression suite. The test is executed in-process before any git operation; only upon 100% test pass is a GitHub pull request dispatched.
